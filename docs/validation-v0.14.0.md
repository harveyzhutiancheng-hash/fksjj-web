# 0.14 验证范围

源码测试、发布机制测试、真实浏览器检查和线上发布结果分别记录。本文件说明测试方法与边界；当前提交的实际 CI 结果以 GitHub checks 为准，不能从本文件或版本号推断已经上线。

## 源码与 HTTP 回归

```sh
npm run test:source
python3 -m unittest api.test_api api.test_boundaries -v
npm run test:http
```

前端用非秘密 Storage/fetch 夹具验证账号迁移、身份冻结、冲突的云端/本地选择、迟到响应和认证成功后的存储写失败。真实 localhost HTTP 回归运行临时 API 与独立合成 Cookie 会话，验证身份错配返回不泄露存档的 403、正常读取、CAS 冲突和存档持久性。它们不使用真实玩家账号或正式数据库。

`deploy/test_manual_browser_checks.py` 对五类内存注入及其失败保护执行 Node 测试，并明确区分注入与真实操作。`api/test_preview.py` 验证候选路径白名单、哈希、缓存隔离和关闭预览；不把普通新标签称作独立浏览器上下文。

## 发布机制

发布相关测试使用临时文件树、固定非秘密签名密钥、受控时钟及命令桩，覆盖：

- repo/ref/commit、静态清单和归档摘要绑定；路径穿越、链接、额外文件和解压限额拒绝。
- HMAC 签名、时效、持久去重、并发和未知结果阻断。
- 每次发布的审计记录、首次注册前的排他尝试标记及跨流程两账号总额度。
- API receipt 的真实检查项、代码与清单绑定和最多十五分钟有效期。
- 旧树完整性、预期 current 的 CAS、原子切换和仅静态回退。

CI 不安装服务器服务、不修改 Nginx、不创建正式密钥，也不触发发布工作流。服务端首次接入的路径、身份、能力和调度须另行审查，见[接入说明](github-release-setup.md)。

## 真实验收边界

实际界面、手机布局、WebGL、双标签写入锁和真正独立 Cookie/Storage 上下文需要真实浏览器检查。Node、视口参数、普通新标签或 HTTP 客户端不能替代它们；网络错误和配额错误注入也不等于真实断网或耗尽存储。

本次候选若采用明确的人工 QA 豁免，记录必须保留 `waived_not_run` 与对应版本/清单，不能写成测试通过。豁免不适用于 API 身份隔离、CAS、CSRF/Origin、Secure Cookie、重启持久性或任何文件完整性门禁，也不自动延续到后续版本。

确认发布成功需要同一次运行的认证终态、公开清单与版本/摘要匹配；仅上传 ACK、暂存或健康 200 不足以证明已上线。超时、断连或不确定结果必须先核验，不自动重试、清理记录或回退数据库。
