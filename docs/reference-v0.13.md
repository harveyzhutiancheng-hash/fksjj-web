# v0.13 生鱼片与六格加工队列

核对日期：2026-10-20；目标仍为抖音小游戏。此轮使用上一轮保存的公开实录画面，补查居民订单规则；没有索取用户录屏。

## 可确认的配方和画面

[你过来呀丫丫的公开实录 BV1Vt9MByEP8，24:54](https://www.bilibili.com/video/BV1Vt9MByEP8/?t=1494)可见切鱼厂2级，生鱼片产品选中：鲜鱼6、1分30秒、库存21/50，顶部六个生产槽。[25:35](https://www.bilibili.com/video/BV1Vt9MByEP8/?t=1535)可见材料厂的六槽队列。

本地逐帧证据沿用 `test-results/v0.12-qa/research/detail-1494s.png` 和 `detail-1535s.png`，对应解码记录见同目录 `manifest.json`。录像本身渠道未独立确认，不能宣称为抖音当前客户端逐项对证。

本轮按可见数值将新生鱼片生产改为：每份6鲜鱼、90秒、产出1份；成品和已排批次共同预留50份容量。工厂从3批扩到6批，先入先出；入队时扣料，完成后领取。切鱼厂新建后即可安排生鱼片，2级开放鱼肠线；最低等级、首餐5份门槛仍为项目衔接规则。当前新升级到2级止步，避免为没有新配方或产能收益的3级收费；旧档已有3级原样保留，这一门槛是项目保护规则。

## 存档兼容

内部生产版本5升6；外层存档键和版本不变。

- v1–v5已付工厂批次保留原输入、输出、总时长、剩余时间，不重收费用。
- 旧切鱼厂已经生成的尾货保留，由“已备好的生鱼片”入口领取；新队列和旧尾货共享50份容量。
- 旧自动生产是完成时才扣鱼。未完成的0–10秒旧进度按比例折成0–90秒保留工时，只抵扣第一次成功入队的生鱼片批次时间；仍完整扣新配方原料。失败入队不消耗工时。该折算是迁移兼容政策，并非原作机制。
- 旧切鱼厂工人回到空闲人口；切鱼厂新生产只在队列推进，不再暗中自动消耗鲜鱼。已经加工出的尾货领取仍计入首餐生产累计。
- 新档缺工时字段默认0，不从旧progress字段反复推导。坏工时、超容量存货、未来生产版本触发锁档保护，保留原始存储。

仍保留每批1–10件与整批领取，因此六格目前是六个“批次”，尚非原作逐件占槽的完整行为；已完成未领取的批次也占格。旧工时已满90秒时可立即完成新一份，即使旧鱼肠线仍在排队，这是旧自动切鱼原本与鱼肠线并行的迁移兼容例外。

## 指引与界面

首餐任务、居民缺料入口和营地切鱼厂均直接进入生鱼片加工页；缺鱼可以去钓鱼。加工页保留升级入口、显示单次原料/时间、六格状态与旧尾货；320×568、390×844、844×390使用固定操作底栏，产品详情区域可滚动。

首餐须累计真实领取5份食物后才能交付，资源奖励不替代生产累计。现有food还兼容农田和旧海上厨房产物，完整食品分类仍待后续拆分，不据此宣称所有食物都已符合原作。

## 居民订单研究结论

[广州益玩2025-12-10的《新手开荒第一天（下）》](https://game.xiaomi.com/viewpoint/1672495402_1765332000202_13)描述居民订单有每日上限；没有提供完整次数成长、刷新价格、刷新冷却或每日重置时刻。详见[本轮检索记录](reference-v0.13-orders.md)。

实录的12/12、12/18计数不能独立证明每天固定12次，也不能证明无限循环。当前保留11份可达居民需求、20项故事目标和14项后续建设任务；本轮不新增未经确认的刷新数值或不可达的12/15/24需求目标。
