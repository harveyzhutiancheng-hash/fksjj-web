# v0.13 居民订单刷新与每日次数：限时研究结论

核对日期：2026-10-20。沿用agent-reach公开检索流程，仅正常web搜索和公开页面阅读。没有登录、cookie、代理或绕过验证；未改项目运行代码。目标为抖音小游戏，跨渠道厂商攻略和具体实录渠道差异仍保留。

## 最小确证

**发行方发布的玩家攻略明确说居民订单有每日上限，但本轮没有查到具体次数、次数增长条件、刷新费用或重置时刻。不能写成固定12次，也不能写成无限循环。**

### P1：发行方原文，可直接阅读

- 标题：[玩家攻略丨新手开荒第一天（下）](https://game.xiaomi.com/viewpoint/1672495402_1765332000202_13)
- 作者/账号：广州益玩；日期2025-12-10 10:00。
- 直接短证据：正文“居民订单数量有每日上限”。这是EXP来源一节中的说明，不提供每日次数表。
- 同页还称每日居民订单奖励有10个蓝图、30个加速沙漏。这是奖励数量，不能把10或30转成每日订单次数。
- 确定性：能够确认这篇跨渠道玩家攻略描述过每日上限；不能将2025年攻略当作抖音当前完整数值配置。
- 缺少：上限具体数值、何时从12变18、人口/等级/VIP/赛季与上限的关系、每日重置时刻、刷新是否计次、刷新价格和冷却。

## 实录的明确推断边界

已有实录BV1Vt9MByEP8可见12/12时仍展示未满足订单，后来出现12/18。它支持分母会变化、12/12不等于所有订单UI立即消失；但单纯展示订单不证明超过该值后还能成功提交，更不能证明订单无限。

1285→1285.5等连续交付画面切换了居民标签，不能单靠不同居民依次出现就断言“同一居民每次满足后随机刷新一份订单”。此前确认的每份原料和奖励仍有效；重复池规则、同配方重复概率以及次日刷新均未取得直接操作证据。
